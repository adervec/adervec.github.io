adervec.github.io / cowork

AI cowork sync

// what it is

Every app here can hand its data to an AI agent and take the answer back, through a plain folder on your disk: the app writes a cowork.json manifest plus request files, an agent (Claude Code via CoworkSyncHub, Claude Desktop pointed at the folder, or a person) writes reply files beside them, the app imports the reply. Nothing goes through a server you don't run.

// one panel, every app

The panel below is the exact same component every app shows — same words, same states, same buttons — no matter what the app around it looks like. CoworkSyncHub shows the same panel for every connected app, where the buttons run the agent instead of writing files.

// states

  • idle — nothing asked yet.
  • PENDING — a request is newer than any reply.
  • answered — a reply landed after the latest request.
  • STALE — pending for over 7 days.
  • note — something's wrong with the folder; the text says what.

// try it

Pick any scratch folder. The panel writes a tiny manifest and request into it; drop a reply.json in there (any JSON) and press Check for replies.

// for app authors

<script src="https://adervec.github.io/cowork.js"></script>
<script>
cowork.mount(document.getElementById("sync"), {
  app: "myapp",
  manifest: { protocol: "cowork-manifest", protocolVersion: 1, app: "myapp",
    channels: [{ name: "coach", request: ["coach/request.json"],
                 instructions: "coach/INSTRUCTIONS.md", replyPath: "coach/reply.json" }] },
  files: ch => ({ "coach/request.json": buildRequest(), "coach/INSTRUCTIONS.md": INSTRUCTIONS }),
  apply: (ch, reply) => importCoachReply(reply)
});
</script>

Apps that already drive their own folder keep that logic and use mode="data": feed the panel {app, channels, actions} and listen for cowork-action. Theme it only through --cowork-* custom properties; the rest is shadow DOM on purpose. Protocol details: CoworkSyncHub / COWORK-PROTOCOL.md.

// the other two contracts

Because every app lives on this origin, they share two small localStorage notes with the portal: portal-installed (an app marks itself when it runs installed, so the portal can launch that copy) and portal-activity (an app appends [unixSeconds, slug, kind, amount] when you actually do something — a set, a chapter, a ride — which feeds the character sheet on the front page; amount is roughly minutes of effort ÷ 10, so a short session is 1; keep the array under ~2000 entries). Both stay in your browser.
